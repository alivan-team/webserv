Static GET / custom index

Architecture, served as a static file.

This page demonstrates a location-specific root and index file. The server reads the file, chooses a content type, builds HTTP headers and sends the response through its non-blocking client socket.

Event loop

Listening sockets, clients and CGI pipe descriptors are coordinated through one readiness mechanism.

Request parsing

Headers and bodies are accumulated across reads, including Content-Length and chunked request bodies.

Routing

Longest matching location selects roots, methods, indexes, autoindex, redirects, uploads and CGI settings.

Responses

Static files, status codes, error pages, uploads, DELETE and CGI output are turned into HTTP responses.
